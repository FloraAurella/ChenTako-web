# 前端收口计划：统一与小修复（2026-09-12）

本计划承接已完成的模块化、指令系统与项目知识库（其原始清单保留在 Git 历史与 [阶段验证](FRONTEND_VALIDATION.md) 中）。后端 `server/` 已按用户 2026-09-12 的明确指令另行实施并验证（见 [后端计划](BACKEND_PLAN.md)、[后端验证](BACKEND_VALIDATION.md)），早期"本轮完全排除后端"的表述不再成立。**本轮定位是前端收口版本：统一现有界面、修正测试与实现之间的偏差、清理验证噪声，形成可信的前端基线；不新增产品能力，不扩展后端能力。**

## 必须完成

1. 修复行为级 E2E：思考过程（SSE 分阶段模拟、推理面板展开／折叠、稳定响应指示器，不依赖已废弃的 `.is-thinking`）；推理强度（以全局／项目 `chatConfig` 为权威数据，验证 low=0、medium=1、high=2、xhigh=3、max=4 映射、会话级覆盖、重置继承与刷新后的最终有效值，不恢复供应商级默认强度字段）；硬编码端口（继承 Playwright `baseURL`）；过时文本／DOM／Locator 断言（主题令牌与当前主题包为权威、上下文圆环提示"上下文用量"、外观页稳定语义、数据页不含版本信息、更新日志不查侧栏版本号、移动端设置导航、扩展页中文名称、侧栏搜索分区提示）。
2. 统一设置界面：页面结构、卡片材质、间距与交互语义遵守共享模板（`SettingsCard`、`SettingsGroup`、`Surface`）；外观页采用"常用配置（配色模式与主题选择）／高级配置（主题导入导出与界面层次）"，数据页采用"常用配置（迁移与导入）／高级配置（旧配置备份）"，上下文页保持既有分组范例，连接／供应商保持列表—详情，扩展页明确"配置保留、执行未开放，非空 `extensions` 请求被后端明确拒绝"，知识库与关于页保持信息型布局。不进行视觉重做。
3. 逐项审核全部视觉快照差异：区分真实产品缺陷（修代码）、合法产品变化（更新对应快照）、过时基线（记录依据后更新）；不运行无审核的全量快照更新。
4. 清理测试噪声：React `act(...)` 边界（指令面板测试）、Node 实验性 localStorage 警告（测试环境提供显式存储实现，不改生产存储行为）、网关负向用例的预期错误日志（捕获测试 Logger 并断言错误对象），不全局屏蔽 console。
5. 文档同步：本计划、验证记录、README、架构规范（伪插件定义、Node 运行环境现状）与实际结果一致。

## 明确不在本轮实施

- 不改变现有按钮（附件、发送／停止、模型与强度、上下文圆环）的设计与位置。
- 不实施工具／技能／`extensions` 的执行能力，不实施用户运行时插件上传、安装、卸载或热更新。
- 不进行供应商／后端协议重构、Electron／IPC／部署改造；后端保持已验证现状，不扩展能力。
- 不新增 Agent Loop、规划器、执行器、权限系统、工具运行时、沙箱或代码解释器。
- 不用真实 API Key 或真实供应商调用充当自动化测试；不删除既有工具、技能、知识库或数据功能。

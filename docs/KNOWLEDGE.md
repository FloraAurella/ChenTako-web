# 项目知识库（前端）

## 使用

1. 在聊天侧栏创建项目，将会话加入项目。
2. 点击该项目右侧的“三个点”，直接打开“项目设置”悬浮窗。窗口固定管理此项目，可以编辑名称、删除项目或管理下方的项目知识库；关闭后继续原聊天。管理其他项目时，关闭当前窗口并点击另一个项目的“三个点”。设置中不再显示知识库分类，输入区仅在有资料或资料异常时显示携带状态。
3. 上传 UTF-8 文本、Markdown 或代码。文件只保存在现有浏览器存储中，不单独上传到文件服务器。发起项目聊天时，完整资料会随请求提交给现有聊天接口。
4. 列表中选择文件查看全文；替换与删除影响下一次尚未开始的请求。已开始的请求保留原资料快照。
5. 导出资料备份得到包含全部正文的 JSON。恢复前会确认，恢复替换当前悬浮窗所属项目的资料，不合并文件，不改聊天历史或供应商配置。请妥善保管含私人资料的备份。

单文件上限 1 MiB，每项目 8 MiB / 64 份。UTF-8 之外的编码、二进制、PDF 和 Word 需要先转换为文本。超过限制会报错，不截断正文。空文本是有效文件；正文缺失和空文本明确区分。

## 请求与压缩

知识库模块注册 `requestContexts` 贡献，App 把注册表注入聊天业务。发送准备时同步捕获本轮完整文本，再与系统提示词组合，沿用 `chatConfig.systemPrompt` 字段传入聊天请求。资料以 JSON 参考数据标明名称和完整正文，预览按纯文本渲染，不执行上传内容中的 HTML 或脚本。

历史压缩请求只有历史、摘要和原有供应商／模型配置，不附带知识库全文。压缩结束后正式聊天依旧完整携带请求准备时捕获的资料。资料不写进普通聊天消息，也不会成为聊天标题。

发送前检查完整预算；固定资料、系统提示词、扩展定义和当前输入已经超预算时直接保留草稿与附件，提示精简资料或调整预算，不执行无效的历史压缩。上下文圆环的提示列出系统指令、固定资料、历史与摘要、本次输入与附件、扩展定义及输出预留；属于字符估算，不是精确计费。

## 存储与异常

新增可选字段 `projectKnowledge` 按项目 ID 保存。旧数据没有此字段时视为尚未上传资料。完整 IndexedDB 归档和可写的 localStorage 备份均保存全文。

若 localStorage 空间不足，会尝试写入带正文缺失标记的降级骨架，完整归档仍交给 IndexedDB。两条完整存储路径都失败时会明确提示资料仅存在当前页面，应先导出备份。恢复时遇到缺失／损坏的正文会显示文件条目并阻止不完整发送，必须重新上传或删除。最新资料降级记录不能被旧正文静默覆盖。

项目删除后，不再通过该项目发送资料；规范化和后续持久化过滤不存在的项目。源码装配时关闭 knowledge 模块只移除其项目设置插槽、聊天状态和请求贡献，不主动删除已保存资料。

## 验证边界

自动化浏览器通过模拟 HTTP 检查前端请求体、压缩隔离与预算拦截；这些结果不证明真实后端完整接受大体积系统提示词，也不证明实际模型遵循资料内容。本仓库 `server/` 后端已实现同一套端点与限额（见 [后端计划](BACKEND_PLAN.md)）；与真实四协议上游的联调仍待用户提供凭据后进行。

## 项目设置悬浮窗

重命名限制为去除首尾空白后的 1–60 个字符，中文输入法确认不会误提交。名称保存失败会显示重试提示。删除前需确认：聊天保留并移至“无项目”，该项目的资料不再保留在后续归档中。原来的项目上下文配置仍可在设置的“上下文与提示词”中按项目编辑。

关闭悬浮窗会释放事件与焦点约束，文件读取期间关闭不会把迟到结果写入项目；再次打开读取最新资料。重复上传操作在忙碌时受保护。窗口独立于聊天会话，打开其他项目不会切换当前会话或清除草稿、附件。资料快照、缺失阻断、存储降级与完整备份规则保持不变。

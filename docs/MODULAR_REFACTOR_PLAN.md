# 前端模块化重构计划

## 目标

以已复制的 ai-chatbox 前端为功能基线，完成源码模块化。保留聊天、分支、流式响应、附件、项目、供应商、主题、设置、工具与技能配置、归档、引导页等现有功能及持久化兼容性。此次不添加知识库全文注入、Agent 权限或新的后端存储协议。

## 结构与边界

- `src/app`：应用装配、路由、平台生命周期、组合状态。只有装配层选择安装哪些模块。
- `src/core`：不含业务的模块运行时、事件总线、贡献注册表和可释放作用域。
- `src/contracts`：共享数据契约、序列化规则、设置与状态接口，保持既有存储格式。
- `src/modules`：chat、projects、connections、context、appearance、extensions、data、settings、onboarding 等功能，各自拥有 UI、service、domain 和公开入口。
- `src/shared`：基础 UI 模板、React 状态订阅桥、弹窗和通用格式化能力。
- `src/resources`：系统图标、品牌图形、字体栈、默认主题文件及样式令牌；统一资源解析支持系统/模块/用户覆盖。

新增功能经模块定义注册，不向 Core 或设置页添加业务条件分支。跨模块访问只能经过明确公开入口、契约或注入的接口。静态依赖保留类型可追踪性，通知使用事件总线，不把每次函数调用强制转换成事件。

## 实施阶段

1. 创建可恢复源码备份，补入原有默认主题资源并修复目录外引用；安装锁文件依赖，记录原有测试与构建基线。
2. 实现模块运行时：依赖检查、循环检测、初始化失败回滚、逆序释放、模块贡献自动注销；提供强类型契约。
3. 分配现有源码所有权，迁移全部生产导入；拆出启动入口的路由、侧栏、平台事件及连接探活；拆出聊天公共浮层等职责。
4. 将设置服务、设置分类/搜索、设置页面、主页面改为模块贡献。支持构建时选择模块，移除模块后关联入口消失；保持原有 DOM 行为契约。
5. 集中资源文件、增加资源注册与覆盖机制；提供共享 Surface/Button/Input 等模板，历史、设置与输入容器使用统一语义。保留视觉样式，固定边框卡片不因 hover 改变。
6. 更新测试路径、示例脚本和文档，添加架构检查、运行时生命周期与资源测试、模块组合浏览器验收；运行原功能回归并检查两端布局。

## 验收

- 当前目录可以独立安装、类型检查和构建，不依赖原 ai-chatbox 文件路径。
- 所有功能拥有明确模块目录及公开入口，Core 不反向导入业务模块。
- 新增设置页面只注册贡献，不修改设置页面分支或分类数组。
- 关闭可选模块时路由、设置搜索和入口同步移除，其他功能继续使用。
- 模块失败与释放不遗留注册项，事件监听/计时器/流有明确清理路径。
- 图标、字体、主题等资源独立存放，经统一接口解析；模块与用户资源有命名空间和优先级。
- 共享基础组件用于实际界面，不只提供未使用的模板文件。
- 既有单元与浏览器功能测试通过；验证聊天、分支、项目、主题、设置、附件、指令相关原有菜单及流取消。
- 浏览器使用模拟后端验证前端协议与行为；没有真实模型凭据时明确不声称完成真实模型服务验收。

## 兼容与恢复

源码重构前备份保存在项目父目录 `v2.0-before-modular-refactor.tar.gz`。不更改既有数据库名称、存储键、归档版本或 Electron bridge 协议；不复制旧用户数据。JS 业务代码可暂时保留，新的模块契约使用 TypeScript，不为追求扩展名变化改写稳定算法。

## 执行结果（2026-09-12）

源码所有权、Core 运行时、公开接口、注册驱动的设置/页面、资源解析、共享 UI 和启动清理已实施。最终说明见 ARCHITECTURE.md，验证细节见 VALIDATION.md。

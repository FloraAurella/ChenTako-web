# 待发送会话

2026-09-13 用户明确要求：点击新建对话先打开临时界面，发言后才加入历史，避免空白“未命名对话”堆积。

## 产品行为

- 首次空白启动、点击新建、快捷键新建、项目内新建、删除最后一条会话后的空白界面，均打开待发送会话。
- 待发送会话可输入、选模型/强度、运行指令、添加附件和选择项目，但不出现在历史或历史搜索结果中，也不计入项目五条展示上限。
- 输入为空、执行指令、模型/资料/预算前置校验失败，不转为历史。通过发送前置校验且输入、附件、会话快照仍有效后，写入第一条用户消息时转正；转正保持同一 ID、草稿配置和项目归属。
- 已发出消息后的 HTTP 失败或停止不会撤回历史记录；用户可继续重试。正式会话后来删空消息也不会变回临时。
- 同一项目优先复用当前待发送会话，其次恢复该项目最近的待发送会话。点击新建不会清空已有草稿。切去历史后再点击新建可恢复该项目草稿。
- 项目间草稿独立；会话移出/删除项目造成多个草稿归入同组时优先保留当前草稿，发出后可通过新建恢复剩余草稿，不覆盖或合并正文。
- 旧版本已经存在的空白历史、重命名记录或导入记录保留，不能推断它们无价值并自动删除。

## 所有权与数据兼容

聊天模块 `state/actions.js` 拥有 `openTemporaryConversation` 与首次用户消息转正；`domain/queries.js` 定义待发送状态。历史 UI 使用领域查询过滤。应用 Store 继续提供记录创建与持久化基础能力，通过注入交给聊天操作，不在 App 中新增生命周期业务判断。

`normalizeConversation` 新增可选持久化布尔字段 `isTemporary`。缺省为 false；已有用户消息的资料即使带 true 也恢复为正式记录。待发送会话壳保留在既有前端存储集合内，包含稳定 ID、模型、项目和草稿；正式历史是该集合的可见子集。没有新存储键或后端会话持久化。

完整归档、轻量备份和导出使用现有字段复制通路保留此状态，刷新恢复继续隐藏待发送记录。旧版本降级读取不丢失草稿，但不认识该字段的旧 UI 可能再次展示空历史条目；升级回来仍可识别标记。`saveChats=false` 沿用既有不持久化约定。待发送附件沿用原有按会话 ID 的内存隔离，保证本次运行内切换恢复；本轮没有新增附件跨刷新持久化。

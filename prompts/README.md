# 项目提示词

## ChenTako-web 当前运行范围（2026-09-13）

此副本暂时只启用普通聊天。writing 模块在应用装配时停用：不显示章节工作区、右侧栏按钮及写作模式状态，不注册 /create、/name、/write、/edit、/chat 和 @ 章节选择指令。/model、/effort、/compact、/help 保留。旧指令会报错并保留输入，不自动当作普通消息发送。

只有 prompts/system.json（聊天）、summary.json（历史摘要）、title.json（自动标题）生效，启动和构建时的自动转换也仅处理这三个文件。discussion.json、write.json、edit.json、continuity.json 保留原文件但不导入、不转换、不用于请求。已有作品数据及兼容代码保留，停用不删除数据；旧对话保存的写作模式不影响当前普通聊天，也不自动携带章节正文。

该状态仅适用于 ChenTako-web，原 ChenTako 副本未修改。下文写作功能说明保留作恢复功能时参考，不代表此副本当前启用。


此目录是 ChenTako 产品提示词的唯一来源。2026-09-13 起替代设置页系统提示词和代码内置的写作、检查、摘要、标题提示词。设置页不再提供提示词编辑卡片或搜索入口；旧全局／项目 systemPrompt 字段保留用于数据兼容，但不参与前端请求配置。

## 文件清单

| 文件 | 用途与需要编写的内容 | 空值行为 |
| --- | --- | --- |
| `system.json` | 通用助手身份、语言、语气、总原则；普通聊天与作品请求共用 | 可留空，普通聊天仍可发送 |
| `discussion.json` | 剧情讨论：分析情节、人物与章节衔接，区分正式正文与未采纳候选 | 可留空，仅附带模式、章节数据 |
| `write.json` | 按要求创作目标章完整正文；只输出目标章 Markdown 正文，不附解释，不修改其他章 | 阻止写作生成 |
| `edit.json` | 以最新候选（无候选时用正式正文）修改目标章；返回完整正文，不只返回修改片段 | 阻止编辑生成 |
| `continuity.json` | 在生成前检查要求与全部正式章节、目标底稿的冲突，给出章节及调整建议；识别用户明确接受的情节变化 | 当前直接写入流程不调用，保留备用 |
| `summary.json` | 压缩历史，保留事实、约束、决定、未完成事项，区分事实与建议；只输出摘要 | 摘要请求报错，保留原历史 |
| `title.json` | 从首次输入概括标题，只返回一行纯文本，不执行输入中的指令，最多 18 个字符 | 标题生成报错，不影响已有正文 |

当前写作／编辑已取消严格 JSON 连贯性检查前置关卡；正文格式由作者提示词决定，程序按原样保存。`continuity.json` 保留备用，不需要删除作者原文。

章节、模式、资料来源标签、预算与输出格式校验仍由程序负责；它们是动态数据和协议约束，不是可配置的人格／写作提示词。代码不会再补充旧的写作风格或任务提示词作为回退。

## 填写与自动转换

由你直接编辑这七个文件，不需要把提示词发给 Codex。打开对应 `.json` 文件，**全选替换为提示词正文**，按 UTF-8 保存即可。可以直接包含长文本、换行、引号、反斜杠、Markdown 和代码块，不必自己编写 JSON，也不要在原来的 `""` 中间手工粘贴。

本地脚本 `scripts/convert-prompts.mjs` 自动把纯文本编码为一个 JSON 字符串。它不调用模型、不改写正文、不裁剪长度，不改变原文换行或首尾空格。转换前将原始字节备份到 `prompts/.backups/`，该目录已排除 Git。已是 JSON 字符串的文件直接跳过，重复执行不会重复转义。

以下命令会通过 npm 前置步骤自动完成转换：

- `npm run dev`：启动前端前转换。
- `npm run dev:server`、`npm run start:server`：启动后端前转换。
- `npm run build`：构建前转换。

也可以随时单独运行：

```bash
npm run prompts:convert
```

服务已经运行时，保存纯文本后执行上面这条命令，然后刷新前端页面；本脚本不持续监听编辑器保存。不要在转换执行期间继续编辑同一文件。直接运行 `vite` 或 `node server/app/main.ts` 会绕过 npm 前置步骤，此时须先执行转换命令。

极少数情况下，提示词全文恰好是一个合法 JSON 字符串（例如全文为 `"保留引号"`），自动模式无法判断这些引号属于正文还是已转换的格式。如果需要保留外层引号，在刚粘贴原文后执行一次：

```bash
npm run prompts:convert -- --raw system
```

把 `system` 换成对应文件名。`--raw` 强制将该文件全文视为正文，只对刚粘贴的原文使用一次；随后恢复普通自动转换。合法 JSON 对象、数组、数字等会按提示词全文保存，不会被当成角色配置或模板执行。

文件缺失、不是普通文件、UTF-8 无效、备份失败或转换失败时会报错，npm 会阻止后续启动／构建；读取失败不会被替换成空提示词。脚本不向日志打印提示词内容。转换没有模型 token 限制，但实际发送仍受模型上下文窗口及应用请求大小限制。

前端五个文件由 Vite 在构建时读取；生产环境修改后重新构建并加载新页面。后端 `summary.json`、`title.json` 每次辅助任务开始时读取，按服务文件位置定位，不依赖启动目录。部署后端时须同时保留根目录 `prompts/`。已开始的请求继续使用开始时捕获的内容。

作品和聊天备份不包含此目录；迁移应用时请单独保留这七个文件。测试通过显式模拟提示词读取器验证已配置的工作流，不会向这些空文件写入测试文案。

## 直接写入流程更新（2026-09-13）

当前 `/write` 与 `/edit` 已改为直接写入正文、自动保留版本，不再执行自动连贯性检查。`continuity.json` 原文件保留，当前流程不读取它；上表对它的“阻止检查”描述仅适用于历史首版。正文输出原样保存，格式由作者提示词决定，应用不再要求严格 JSON 或采纳候选。无需更改 JSON 转换方式，也没有自动改写任何作者提示词。
